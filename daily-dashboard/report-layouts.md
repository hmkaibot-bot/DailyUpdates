# 各報告版面（reports[]）

一次 run 產生多份，數字**只算一次**再組裝。每份對應 config `delivery.reports[]` 一項。
所有數字沿用各 section 已定義嘅算法（營收=最後完整日、賣車淨利=毛利×0.9、保險=保費×15% 等）。

---

## ① management → #每日匯報（`C0BDLSKM2FQ`）—— **精簡前頁（每日）**
管理層只要「數字 + 例外 + 一句洞察」。**唔重複昨日每線細節**（部組頻道有）。
```
:bar_chart: *管理 Daily* — {YYYY-MM-DD}｜本月 {elapsed}/{days_in_month} 日 應達 {pace}%
*💰 集團 GP*：$X / $1.0M（*{%}*）｜ 距標 $X ｜ 預估埋月 $X
*📊 MTD 達成*：零售 {%}｜車房 {%}｜賣車 {%}｜租車 {%}　（落後標 ⚠️）
*💵 現金*：入 $X / 出 $X ｜ 應付 $X　　*📦 在庫*：鎖資金 $X（車齡>60:{k}）
*🚨 例外*（只列非零）：{售價未入 k｜續保到期 k｜車房未來預約不足…}　或 ✅ 今日無異常
👉 一句跨線洞察
```
- **GP 一行必填**（見 05 section 計法）。四線只出達成%，唔出每日細節。
- 例外**只列非零項**（包括新增「車房未來預約不足」）。
- **GP 分項嘅口徑標註**：只有**零售**仍係毛利率假設（34%）；車房用 Q3b 嘅 `g_gp` 實數，但係**零件貢獻毛利、未扣師傅人工**，同其餘分項層次唔同，腳註要講明；賣車/租車係真實淨利。唔好再寫「零售/車房用假設」，亦唔好把車房講成「真實毛利率」。

### 週報（逢星期一，附喺同一頻道）
`config.reports.management.weekly_blocks` = GitHub 熱門 / 社群熱門 / 生產力建議 / Skill 工作流程 / 停滯工作。
星期一先出呢啲「閱讀性」內容，其餘日子唔出，保持每日精簡。

- **利潤一定要兩個都出**：`gross_profit`（未計佣）先係老闆喺 26KING app 見到嘅「已實現利潤」；`net_profit`（×0.9）先係追 $250k 目標嗰個。淨報一個就一定會有人覺得對唔上。
- 「可售在庫」= `stock_cnt`（已剔走待埋單嗰批），唔好同 pipeline 重複計。
- 應收數要標明「口徑同 app 未對齊」，唔好扮啱（見 `queries.md` 已知未對齊一節）。

## 組裝規則
- **部組頻道只出自己嘅數**，唔好夾雜其他線或集團 GP。
- 每份最後一行 `:point_right: 今日：…` = 該部組今日行動。
- 任一 block 資料失敗 → 標「⚠️ 今日無法取得」，該份其餘照出；任一頻道發送失敗 → fallback DM，其餘頻道照發。
- 首次上線用 `send_mode: draft` 發草稿畀老闆驗收。

### 車房比較欄嘅硬規則（Q3b comparable flag）
| 情況 | 出咩 |
|---|---|
| `g_wow_comparable` / `g_lastmonth_comparable` = **false** | 「—（新來源 {g_src_start} 上線，未夠比較期）」<br>**絕對唔准出 ▼100%、唔准當 $0 計跌幅、唔准 fallback 去 BC 補數** |
| comparable = **true** 而 cnt = 0 | 「$0（當日冇交車）」 |
兩者意思完全唔同：混為一談會把「冇生意」報成「新系統」，或者反過來。
`g_wow` 2026-09-08 自動有數、`g_lastmonth` 2026-10-01 自動有數，**唔使改任何檔**。

### 車房毛利嘅措辭
一律叫「**零件貢獻毛利（未計人工）**」，唔准叫「真實毛利」或者攞 71.4% 同舊制 48% 直接比 ——
工時佔收入約 57.5% 而公式完全冇人工成本，48% 反而接近 all-in。
`g_missing_cost_cnt` > 0 要出註：「{n} 張單有零件未入成本，毛利偏高」。
